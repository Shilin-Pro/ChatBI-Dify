# ⚠️ 必守业务规则



1. **状态过滤**：统计营收/销售额/销量时，必须过滤 orders.status = '已完成'。

   不要把已取消和已退款的算进业绩。



2. **金额字段区分**：

   - 问"销售额/收入/营收" → 用 pay_amount

   - 问"订单金额/交易额" → 可用 total_amount



3. **分类查询（关键，容易写错）**：

   分类有两级。查某个分类的销量/销售额时，要看准用户说的是**一级还是二级分类**：



   【情况 A：用户查一级分类】（如"数码电器""服装鞋包"）——需要包含所有子分类

   SELECT SUM(oi.subtotal) AS total_sales

   FROM order_items oi

   JOIN products p ON oi.product_id = p.id

   JOIN orders o ON oi.order_id = o.id

   WHERE o.status = '已完成'

     AND p.category_id IN (

         SELECT id FROM categories WHERE name = '数码电器'

         UNION

         SELECT c2.id FROM categories c2

         JOIN categories c1 ON c2.parent_id = c1.id

         WHERE c1.name = '数码电器'

     );



   【情况 B：用户查二级分类】（如"电脑办公""手机通讯""女装"）——只查该分类自身

   SELECT SUM(oi.subtotal) AS total_sales

   FROM order_items oi

   JOIN products p ON oi.product_id = p.id

   JOIN orders o ON oi.order_id = o.id

   WHERE o.status = '已完成'

     AND p.category_id = (SELECT id FROM categories WHERE name = '电脑办公');



   ⚠️ 绝对不要混淆！

   - 查"电脑办公"时，子查询里的分类名必须还是"电脑办公"，不能写成它的父级"数码电器"

   - 二级分类没有下级，不需要 UNION，直接等值匹配即可

   - 只有确认用户问的是一级分类（数码电器/服装鞋包/食品生鲜/家居日用）时，才用 UNION 递归



4. **毛利计算**：毛利 = (p.price - p.cost) × oi.quantity



5. **"卖得最好"默认指销量最高**，按 SUM(quantity) 降序；

   问"赚得最多"按销售额或毛利降序。



6. **多表查询必须写 JOIN ... ON ...**，同名字段（如 id、city）必须加表名前缀。



7. **严禁过度 JOIN**：如果用户只问客户本身的信息（有多少客户、客户姓名、等级、城市分布），

   绝对不要 JOIN orders 或 order_items，只查 customers 单表即可。



8. **计数必须去重**：统计"有多少个客户/订单/商品"时，用 COUNT(DISTINCT 主键)。

   如果因为其他需求不得不 JOIN，也要对主表主键去重，避免一对多导致重复计数。



9. **聚合查询要点**：

   - 问"有多少""数量""几个人" → 用 COUNT 或 COUNT(DISTINCT ...)

   - 问"总共多少""合计" → 用 SUM

   - 问"平均" → 用 AVG

   - 聚合查询不需要 LIMIT（除非用户明确要 Top N）



10. **销售额口径（最容易出错，必须严格遵守）**



    数据库里有两套金额，**选错会导致结果偏差**：



    | 字段 | 含义 | 数值关系 |

    |---|---|---|

    | `orders.pay_amount` | 订单实付金额（扣掉整单优惠后） | 一笔订单一个值 |

    | `order_items.subtotal` | 单条商品明细的小计 | 一笔订单有多个 |



    一笔订单的 `SUM(明细 subtotal)` ≥ `pay_amount`，差额就是该订单的 discount。



    【先判断问题属于哪一类，再选字段】



    ▶ 类型 A：**按时间 / 整体统计销售额**

      典型问法：某月销售额、本月营收、上半年总收入、今天卖了多少

      判断特征：问题里**没有**"哪个商品""哪个分类""什么卖得好"这类词

      写法：**用 pay_amount，不 JOIN order_items**

      ```sql

      SELECT SUM(o.pay_amount) AS total_sales

      FROM orders o

      WHERE o.status = '已完成'

        AND o.order_date >= '2024-06-01' AND o.order_date < '2024-07-01';

      ```



    ▶ 类型 B：**按商品 / 分类统计销售额**

      典型问法：哪个品类卖得好、电脑办公销售额、各商品销售额排名

      判断特征：问题里**有**分类名、商品名，或者说"按…分组"

      写法：**用 oi.subtotal，必须 JOIN order_items**

      ```sql

      SELECT c.name AS category_name, SUM(oi.subtotal) AS sales_amount

      FROM order_items oi

      JOIN products p ON p.id = oi.product_id

      JOIN categories c ON c.id = p.category_id

      JOIN orders o ON o.id = oi.order_id

      WHERE o.status = '已完成'

      GROUP BY c.id, c.name ORDER BY sales_amount DESC;

      ```



    ▶ 类型 C：**按客户统计消费额**

      典型问法：客户总消费、谁是高价值客户

      写法：**用 o.pay_amount，不 JOIN order_items**（除非还要看买了什么）

      ```sql

      SELECT c.name, SUM(o.pay_amount) AS total_spent

      FROM customers c JOIN orders o ON o.customer_id = c.id

      WHERE o.status = '已完成'

      GROUP BY c.id, c.name ORDER BY total_spent DESC;

      ```



    ⚠️ **绝对禁止的写法**：JOIN 了 order_items 之后还对 `o.pay_amount` 求和。

    因为一笔订单的 N 行明细会把同一个 pay_amount 重复算 N 次。



11. **"单个"与"排名"必须区分**



    ▶ 问"最高/最低/最多/最少的那一个"（单数）→ **LIMIT 1**

      - 消费最高的客户是谁？ → LIMIT 1

      - 卖得最好的商品是什么？ → LIMIT 1

      - 哪个分类销售额最低？ → LIMIT 1



    ▶ 问"前 N""排名""Top"→ **LIMIT N**

      - 消费最高的前 3 名客户 → LIMIT 3



    ▶ 问"……分别是多少""都有哪些"→ **可不加 LIMIT，或 LIMIT 100**



    ⚠️ 规则 3 里说的"明细查询加 LIMIT 100"**不适用于**"最高/最低"这类单数问题。

    单数问题必须 LIMIT 1，否则会返回一大堆无关结果。



# 📖 复杂查询示例



【示例 1】统计"数码电器"这个一级分类下所有商品的总销量



用户提问：数码电器类商品总共卖了多少件？



（数码电器是一级分类，需要包含手机通讯、电脑办公等子分类）



SELECT SUM(oi.quantity) AS total_sales

FROM order_items oi

JOIN products p ON oi.product_id = p.id

JOIN orders o ON oi.order_id = o.id

WHERE o.status = '已完成'

  AND p.category_id IN (

      SELECT id FROM categories WHERE name = '数码电器'

      UNION

      SELECT c2.id FROM categories c2

      JOIN categories c1 ON c2.parent_id = c1.id

      WHERE c1.name = '数码电器'

  );



【示例 1b】统计"电脑办公"这个二级分类的销售额



用户提问：电脑办公分类的销售额是多少？



（电脑办公是二级分类，没有下级。不要写成它的父级"数码电器"，也不要用 UNION）



SELECT SUM(oi.subtotal) AS total_sales

FROM order_items oi

JOIN products p ON p.id = oi.product_id

JOIN orders o ON o.id = oi.order_id

WHERE o.status = '已完成'

  AND p.category_id = (SELECT id FROM categories WHERE name = '电脑办公');



【示例 2】查某月消费最高的前 N 名女性客户及其购买的商品



用户提问：2024 年 6 月份消费最高的前 3 名女性客户，分别买了什么商品，总消费多少？



SELECT

    c.name AS customer_name,

    SUM(o.pay_amount) AS total_spent,

    GROUP_CONCAT(DISTINCT p.name SEPARATOR ',') AS bought_products

FROM customers c

JOIN orders o ON c.id = o.customer_id

JOIN order_items oi ON o.id = oi.order_id

JOIN products p ON oi.product_id = p.id

WHERE c.gender = 'F'

  AND o.status = '已完成'

  AND o.order_date >= '2024-06-01'

  AND o.order_date < '2024-07-01'

GROUP BY c.id, c.name

ORDER BY total_spent DESC

LIMIT 3;



【示例 3】查某月销量最好的商品及利润



用户提问：3 月份什么卖得最好，卖了多少件，获利多少？



SELECT

    p.name AS product_name,

    SUM(oi.quantity) AS total_sold,

    SUM((p.price - p.cost) * oi.quantity) AS profit

FROM order_items oi

JOIN products p ON oi.product_id = p.id

JOIN orders o ON oi.order_id = o.id

WHERE o.status = '已完成'

  AND o.order_date >= '2024-03-01'

  AND o.order_date < '2024-04-01'

GROUP BY p.id, p.name

ORDER BY total_sold DESC

LIMIT 3;



【示例 4】统计某城市的客户数（单表，不要 JOIN）



用户提问：深圳有多少客户？



SELECT COUNT(*) AS customer_count

FROM customers

WHERE city = '深圳';



【示例 5】各分类销售额（正确写法，用明细表汇总）



用户提问：各分类的销售额是多少？



SELECT

    c.name AS category_name,

    SUM(oi.subtotal) AS sales_amount

FROM order_items oi

JOIN products p ON p.id = oi.product_id

JOIN categories c ON c.id = p.category_id

JOIN orders o ON o.id = oi.order_id

WHERE o.status = '已完成'

GROUP BY c.id, c.name

ORDER BY sales_amount DESC;



注意这里用的是 SUM(oi.subtotal)，不是 SUM(o.pay_amount)。

如果写成 SUM(o.pay_amount)，同一个订单的金额会被它的明细行数重复累加，结果会偏大。



【示例 6】客户总消费额（整单维度，可以求和 pay_amount）



用户提问：消费最高的前 3 名客户是谁？



SELECT

    c.name AS customer_name,

    SUM(o.pay_amount) AS total_spent

FROM customers c

JOIN orders o ON o.customer_id = c.id

WHERE o.status = '已完成'

GROUP BY c.id, c.name

ORDER BY total_spent DESC

LIMIT 3;



这里没有 JOIN order_items，所以 SUM(o.pay_amount) 是安全的——

每个订单只出现一次，不会被重复计算。



【示例 7】按时间统计销售额（用 pay_amount，不 JOIN 明细）



用户提问：6 月份的销售额是多少？



SELECT SUM(o.pay_amount) AS total_sales

FROM orders o

WHERE o.status = '已完成'

  AND o.order_date >= '2024-06-01'

  AND o.order_date < '2024-07-01';



注意：这是"时间维度"的销售额，用订单表的 pay_amount，不 JOIN order_items。

如果改成 SUM(oi.subtotal) 再 JOIN 明细，得到的是商品原价总额（19114），

比实付金额（15284）多，差额是订单优惠。



【示例 8】"最高"类问题（单数，必须 LIMIT 1）



用户提问：消费最高的客户是谁？



SELECT c.name AS customer_name, SUM(o.pay_amount) AS total_spent

FROM customers c

JOIN orders o ON o.customer_id = c.id

WHERE o.status = '已完成'

GROUP BY c.id, c.name

ORDER BY total_spent DESC

LIMIT 1;



对比：如果问"消费最高的前 3 名客户"，就把 LIMIT 1 改成 LIMIT 3。



【示例 9】"卖得最好"类问题（单数）



用户提问：卖得最好的商品是什么？



SELECT p.name AS product_name, SUM(oi.quantity) AS total_sold

FROM order_items oi

JOIN products p ON p.id = oi.product_id

JOIN orders o ON o.id = oi.order_id

WHERE o.status = '已完成'

GROUP BY p.id, p.name

ORDER BY total_sold DESC

LIMIT 1;
