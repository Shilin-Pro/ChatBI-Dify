数据库核心表间关联关系（JOIN 规则）与业务红线
【数据库核心表间关联关系（JOIN 规则）】
- 客户与订单：customers.id = orders.customer_id
- 订单与明细：orders.id = order_items.order_id
- 商品与明细：products.id = order_items.product_id
- 商品与分类：categories.id = products.category_id
- 分类自关联：categories.parent_id = categories.id

【关联关系补充说明】
- 方向约定：上述等号左侧为主表（一的一方），右侧为从表（多的一方）。
- customers → orders 是一对多；orders → order_items 是一对多；orders → order_items → products 构成"订单-明细-商品"的经典三级链路。
- products → categories 是多对一；categories 是两级树状结构（parent_id IS NULL 为一级大类）。
- 没有直接的"商品-客户"关联表，商品与客户的关联必须经过 orders + order_items。

【⚠️ 分类查询的绝对红线（最容易出错，必须严格遵守）】

categories 是两级结构，**一级分类和二级分类的查询写法完全不同**：

一级分类（parent_id 为 NULL）只有 4 个：
  数码电器、服装鞋包、食品生鲜、家居日用

二级分类（parent_id 非 NULL）共 6 个：
  手机通讯、电脑办公  → 属于 数码电器
  男装、女装          → 属于 服装鞋包
  休闲零食、生鲜果蔬  → 属于 食品生鲜
  （家居日用没有二级分类，只有一级）

▸▸ 情况 A：用户问的是一级分类（数码电器/服装鞋包/食品生鲜/家居日用）
   必须包含该分类自身 + 它下面所有二级分类的商品。正确写法：

   WHERE p.category_id IN (
       SELECT id FROM categories WHERE name = '数码电器'
       UNION
       SELECT c2.id FROM categories c2
       JOIN categories c1 ON c2.parent_id = c1.id
       WHERE c1.name = '数码电器'
   )

▸▸ 情况 B：用户问的是二级分类（手机通讯/电脑办公/男装/女装/休闲零食/生鲜果蔬）
   **只查这个分类本身，绝对不要再去找它的子分类**。因为二级分类没有下级，
   如果按 parent_id 去找子分类，结果一定是空的！

   正确写法（等值匹配，简洁直接）：
   WHERE p.category_id = (SELECT id FROM categories WHERE name = '电脑办公')

   ❌ 错误写法（会返回空结果，这是最高频的错误）：
   WHERE p.category_id IN (
       SELECT id FROM categories WHERE parent_id = (SELECT id FROM categories WHERE name = '电脑办公')
   )

▸▸ 判断方法
   看分类名是上面列的哪一类：
   - 4 个一级分类名 → 用情况 A（UNION 递归子分类）
   - 6 个二级分类名 → 用情况 B（等值匹配，禁止递归）

   ⚠️ 特别注意：不要把二级分类的名字套进一级分类的写法里。
   例如查"女装"，绝对不能写成"服装鞋包的所有子分类"（那会把男装也算进去，金额翻倍）。

【标准查询链路】
1. 客户购买了哪些商品 / 客户消费明细：
   customers.id = orders.customer_id AND orders.id = order_items.order_id AND products.id = order_items.product_id
2. 商品销量、商品销售额、品类销售额：
   products.id = order_items.product_id AND orders.id = order_items.order_id （必须再加 orders.status = '已完成'）
3. 品类（含一级大类汇总）销售额：
   先由 categories.parent_id = categories.id 找到一级分类对应的所有二级分类，再由 categories.id = products.category_id 关联商品，最后经 order_items 关联订单。

【核心业务红线】
1. 算业绩/销售额时，必须加上 orders.status = '已完成' 过滤。
2. 算商品销售额，必须用 SUM(order_items.subtotal) 或 SUM(order_items.quantity * unit_price)，绝不能用 SUM(orders.pay_amount)（因为 JOIN 明细后整单金额会重复累加）。
3. 算订单层面的金额（GMV、客单价、实付总额）时，只在 orders 单表内聚合，不要 JOIN order_items。
4. 订单状态口径：'已取消' 和 '已退款' 的订单不计入营收类指标；需要"有效订单数"时应排除这两种状态。
5. 按时间筛选：订单用 orders.order_date（DATE），客户注册用 customers.register_date（DATE），商品上架用 products.created_at，不要跨表混用时间字段。
6. 问"有多少个订单/多少笔订单"时，如果没说"已完成"，就统计全部订单（不加 status 过滤）。只有问"成交了多少单""有效订单"才加 status='已完成'。

【常见错误示范（禁止这样写）】
错误 1：
SELECT SUM(o.pay_amount) FROM orders o JOIN order_items oi ON oi.order_id = o.id WHERE o.status = '已完成';
原因：一个订单有 N 条明细，pay_amount 被重复累加 N 次，金额虚高。

正确：
SELECT SUM(oi.subtotal) FROM order_items oi JOIN orders o ON o.id = oi.order_id WHERE o.status = '已完成';
或者：
SELECT SUM(pay_amount) FROM orders WHERE status = '已完成';

错误 2（查二级分类却递归找子分类，结果为空）：
SELECT SUM(oi.subtotal) FROM order_items oi
JOIN products p ON p.id = oi.product_id
JOIN orders o ON o.id = oi.order_id
WHERE p.category_id IN (
    SELECT id FROM categories WHERE parent_id = (SELECT id FROM categories WHERE name = '电脑办公')
);
原因：电脑办公是二级分类，没有子分类，这个子查询返回空，SUM 也是空。

正确：
SELECT SUM(oi.subtotal) FROM order_items oi
JOIN products p ON p.id = oi.product_id
JOIN orders o ON o.id = oi.order_id
WHERE o.status = '已完成'
  AND p.category_id = (SELECT id FROM categories WHERE name = '电脑办公');

错误 3（查二级分类却用了一级分类的范围，金额偏大）：
查"女装"时写成 WHERE parent_id = (SELECT id FROM categories WHERE name='服装鞋包')
原因：这会把男装也包含进去。

【一句话记忆】
客户看 customers，订单金额看 orders（单表聚合），商品金额看 order_items.subtotal（JOIN orders 加'已完成'），
分类树看 categories 的 parent_id 自关联——但记住：一级分类才递归，二级分类直接等值匹配。
